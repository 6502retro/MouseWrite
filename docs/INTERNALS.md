# How it works

## MW.SYSTEM

`MW.SYSTEM` (2.6.8b, 7,705 bytes) loads at `$2000-$3E18`. It starts with the ProDOS startup-pathname header `JMP $2046 / $EE $EE / 64-byte buffer`. Its own start-up code copies most of itself to `$A000` and loads the other modules (`MW.UI` at `$0803`, `MW.WP`, `MW.KT` …) relative to the current prefix.

3.0 changes exactly these things in it:

| Where | Change |
|---|---|
| bytes 1-2 (the `JMP` at `$2000`) | `$2046` → `$3E1A`, the add-on |
| title box text | `Version 2.6.8b` → `Version 3.0`; the blank box line after it → `Updated by 6502 Retro 2026` |
| Expanded Desktop banner | `Version 2.6.8b` → `Version 3.0` |
| end of file | the add-on (`prebuilt/mwfix3.bin`, 963 bytes) appended from `$3E19` |

The add-on is in two parts:

* **`src/mwfix3.s`, the mover** (at `$3E1A`): copies the body to `$1000` and jumps there. This is needed because the splash uses hi-res page 2 (`$4000-$5FFF`), which the end of the enlarged file would overlap. `$3E19` is kept as `$00` because MW.SYSTEM's own relocation copies `$2307-$3E19` inclusive.
* **`src/mwbody.s`, the body** (runs at `$1000`; uses `$1B00` and a 1K ProDOS buffer at `$1C00`):
  1. `GET_PREFIX`. For `MW.GP` (offsets: document path `$00`, length `$3E`; accessory path `$40`, length `$3F`) and `MW.UI` (speller path `$3B`, length `$3A`), it reads the first 128 bytes and checks each path with `GET_FILE_INFO` (trailing `/` removed). If it fails, it tries *prefix* + `SAMPLES/` / `ACCESSORY/` / `SPELLER/`. If that exists and fits MouseWrite's 62-byte field, it stores it, pads like the originals (`MW.GP` with zeros, `MW.UI` with spaces) and writes the 128 bytes back.
  2. **Splash.** This is skipped when `$0800-$0802` holds MouseWrite's restart signature (`'M' 'W' 'M'^'W'`), the same test MW.SYSTEM makes when it comes back from Basic.System. Otherwise the body reads `MW.SPLASH`: the first 8K (aux half) into `$6000`, copied to aux `$4000` with `RAMWRT`, and the second 8K straight into main `$4000`. It then shows double hi-res page 2 (`80STORE` off, `80COL` on, `$C050 $C052 $C057 $C055 $C05E`) for about 3 seconds at 1 MHz, or until a key is pressed (the key is discarded). After that it goes back to text page 1 (`$C05F $C054 $C051`).
  3. `JMP $2046`, MouseWrite's original start.

Any error (no prefix, a missing or locked file, a short read) skips that step silently.

MouseWrite disconnects `/RAM` and uses all of auxiliary memory itself, so writing aux `$4000-$5FFF` for the splash before it starts costs nothing extra.

## The emulator

apple2js's mouse card ROM is a stub without the Pascal-protocol entry points (`$Cn0D-$Cn10`) or the entries above `$Cn19`. MouseWrite's MouseText ToolKit calls the card's `$Cn1C` entry, and on the stub that lands on `$Cn00`, a `BRK`. [`test/apple2js.patch`](../test/apple2js.patch) points those entries at a `CLC / LDX #0 / RTS` and exposes the emulator objects to the test harness. Real AppleMouse cards, the IIc and the IIgs have these entries. Real hardware needs nothing.

The test harness [`test/harness.js`](../test/harness.js) drives the emulator through Playwright over a small HTTP API. It can move and click the mouse, type, read the 80-column text screen straight from memory, take screenshots, and save the hard disk back to a file.
